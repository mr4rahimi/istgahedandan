## 🔴 بحرانی

### ۱. صفحهٔ اصلی هیچ `<h1>` ندارد

بررسی همهٔ انواع صفحه:

| صفحه | تعداد H1 |
|---|---|
| **صفحهٔ اصلی** | **۰** ❌ |
| **`/reserve/`** | **۰** ❌ |
| **صفحات منطقه** | **۲** ⚠️ |
| `/services/`, `/dentists-list/`, `/mag/`, `/about/`, `/contact/` | ۱ ✅ |
| صفحهٔ دندانپزشک، صفحهٔ خدمت | ۱ ✅ |

در صفحهٔ اصلی، عنوان‌های اسلایدر `<h2>` هستند («بهترین دندانپزشک نزدیک خود را پیدا کنید») و هیچ `<h1>`ی وجود ندارد. مهم‌ترین صفحهٔ سایت بدون عنوان اصلی است.

صفحات منطقه **دو** `<h1>` دارند که سیگنال موضوعی را تقسیم می‌کند.

**رفع:** در `src/app/page.tsx` اولین عنوان اسلایدر (یا یک عنوان توصیفی) به `<h1>` تبدیل شود؛ در `ReservePage.tsx` عنوان صفحه `<h1>` شود؛ در `LocationPage.tsx` یکی از دو `<h1>` به `<h2>` تغییر کند.

## 🟠 اولویت بالا

### ۲. تصاویر بهینه نشده‌اند — ۱.۹ مگابایت در صفحهٔ اصلی

`next.config.ts` → `images.unoptimized: true`، پس تصاویر آپلودی همان‌طور که هستند سرو می‌شوند.

| سنجه | مقدار |
|---|---|
| حجم ۱۲ تصویر صفحهٔ اصلی | **۱۸۸۸ کیلوبایت** |
| میانگین هر تصویر | ۱۵۷ کیلوبایت |
| سنگین‌ترین | `farjam4.jpg` — **۵۱۹ کیلوبایت** |
| بالای ۱۵۰ کیلوبایت | ۵ تصویر |
| نسبت فرمت در HTML | ۴۰ `.jpg` · ۲۲ `.webp` · ۲ `.png` |

مستقیم‌ترین عامل خرابی LCP. برای دایرکتوری‌ای که محتوایش گالری مطب است، بزرگ‌ترین اهرم عملکردی همین است.

**رفع:** روشن کردن بهینه‌سازی تصویر Next (حذف `unoptimized: true`). پیش‌نیازش این است که `sharp` روی سرور در دسترس باشد و منابع کافی باشد. جایگزین کم‌ریسک‌تر: یک بار تبدیل دسته‌ای `/uploads` به WebP با کیفیت ~۸۰.

### ۳. هدرهای HSTS و CSP وجود ندارند

| هدر | وضعیت |
|---|---|
| `X-Frame-Options: SAMEORIGIN` | ✅ |
| `X-Content-Type-Options: nosniff` | ✅ |
| `Referrer-Policy: strict-origin-when-cross-origin` | ✅ |
| **`Strict-Transport-Security`** | ❌ نیست |
| **`Content-Security-Policy`** | ❌ نیست |

حالا که گواهی Let's Encrypt با تمدید خودکار مستقر است، افزودن HSTS بی‌خطر است. در بلوک HTTPS مربوط به istgahedandan.ir در nginx:

```nginx
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
```

> با `max-age` کوتاه (مثلاً ۳۰۰) شروع کنید و بعد از اطمینان بالا ببرید. `preload` را فقط وقتی اضافه کنید که مطمئن باشید همهٔ زیردامنه‌ها HTTPS دارند.

CSP برای سایتی که استایل‌هایش inline است نیاز به دقت دارد (`style-src 'unsafe-inline'` لازم می‌شود) — اولویت پایین‌تر.

### ۴. IndexNow پیاده‌سازی نشده

`/indexnow.txt` کد ۴۰۴ می‌دهد. IndexNow ایندکس فوری در **Bing، Yandex و Naver** را ممکن می‌کند.

این برای این پروژه اهمیت دوچندان دارد: **ChatGPT از ایندکس Bing تغذیه می‌شود**، و طبق تحلیل سئوی محلی، جستجوی محلی از طریق AI در حال رشد است. با توجه به اینکه خزش گوگل تازه دارد برمی‌گردد، مسیر Bing یک کانال مستقل و سریع است.

**رفع:** تولید یک کلید، قرار دادنش در `public/<key>.txt`، و صدا زدن endpoint در نقاطی که محتوا تغییر می‌کند (پنل ادمین و پنل دندانپزشک).

## 🟡 اولویت متوسط

### ۵. اندازهٔ فونت پایه زیر ۱۶ پیکسل

پرتکرارترین اندازه‌ها در HTML صفحهٔ اصلی: **۱۳ پیکسل (۴۵ مورد)** و **۱۴ پیکسل (۴۲ مورد)**. توصیهٔ استاندارد موبایل ۱۶ پیکسل برای متن بدنه است.

چون کل UI با inline style نوشته شده، این کار بدون یک ماژول `theme.ts` مشترک پرزحمت است — که در [`03-issues.md`](./03-issues.md) به‌عنوان مسئلهٔ ۱۹ ثبت شده.

### ۶. نبود عنصر `<main>`

هیچ صفحه‌ای `<main>` ندارد. `<nav>`، `<header>`، `<footer>` و `<section>` هست. برای عامل‌های AI که درخت دسترس‌پذیری را می‌خوانند، `<main>` مشخص می‌کند محتوای اصلی کجاست.

### ۷. ۱۱ دکمه بدون `aria-label`

از ۱۷ دکمهٔ صفحهٔ اصلی، ۱۱ تا برچسب دسترس‌پذیری ندارند. بیشترشان دکمه‌های آیکونی‌اند (اسلایدر، اسکرول) که متن قابل‌خواندن ندارند.

نکتهٔ مثبت: **هر ۲۹ تصویر `alt` دارند** و هیچ `div` با `onclick` وجود ندارد.

### ۸. قانون بی‌اثر در robots.txt

`Disallow: /api/upload/` با هیچ مسیر واقعی مطابقت ندارد — مسیرهای واقعی `/api/admin/upload` و `/api/dentist/upload` هستند. اولی از قبل توسط `Disallow: /api/admin/` پوشش داده شده؛ دومی **پوشش داده نشده**.

### ۹. خزنده‌های AI مدیریت نشده‌اند

هیچ قانونی برای `GPTBot`، `ClaudeBot`، `PerplexityBot`، `Google-Extended`، `Bytespider` یا `CCBot` وجود ندارد؛ همه تحت `User-agent: *` مجازند.

**این لزوماً ایراد نیست.** برای یک دایرکتوری که می‌خواهد در پاسخ‌های AI دیده شود، اجازه دادن احتمالاً درست است. فقط باید تصمیم آگاهانه باشد نه پیش‌فرض. اگر تصمیم گرفتید مسدود کنید، توجه کنید که `Google-Extended` فقط آموزش Gemini را می‌بندد و **هیچ اثری بر ایندکس جستجوی گوگل ندارد**.

## ⚪ اولویت پایین

- **`llms.txt` وجود ندارد** (۴۰۴). گوگل از آن استفاده نمی‌کند؛ فرصت است نه نقص.
- **حجم JavaScript ۶۷۲ کیلوبایت** در ۱۱ chunk. برای اپ App Router با نقشه و ویرایشگر متن قابل‌قبول است، ولی جای بررسی دارد.
- **زنجیرهٔ ریدایرکت در بدترین حالت ۲ پرش** (`http://` + بدون اسلش → HTTPS → با اسلش). حالت عادی ۱ پرش است. برای اصلاح، بلوک پورت ۸۰ می‌تواند مستقیم به نسخهٔ اسلش‌دار بفرستد.

## آنچه نتوانستم بسنجم

**Core Web Vitals میدانی.** فراخوانی PageSpeed Insights با خطای **۴۰۳** برگشت (کلید API پیکربندی نشده) و داده CrUX هم `null` بود. پس LCP، INP و CLS واقعی نامعلوم‌اند.

نشانه‌های خطر غیرمستقیم قوی‌اند (۱.۹ مگابایت تصویر، ۶۷۲ کیلوبایت JS، بهینه‌سازی تصویر خاموش)، ولی این‌ها جای اندازه‌گیری واقعی را نمی‌گیرند. امتیاز ۵۰ در جدول یعنی «سنجیده نشده»، نه «بد».

راه‌های به‌دست آوردنش:
- گزارش Core Web Vitals در Search Console (داده میدانی واقعی کاربران)
- اجرای دستی PageSpeed Insights از رابط وب
- پیکربندی کلید API برای ابزار `pagespeed_check.py`

**بررسی Agent-UX** هم شکست خورد — رندر Playwright نتیجهٔ `about:blank` داد (احتمالاً محدودیت شبکه از موقعیت ما). امتیاز ۹۰ که ابزار گزارش کرد بی‌معناست چون همهٔ شمارنده‌ها صفر بودند. یافته‌های معنایی بالا مستقیم از HTML استخراج شده‌اند، نه از آن ابزار.

**زمان پاسخ از دید گوگل‌بات.** سنجش از اینجا مسیر شبکهٔ ماست نه سرور (که روی خودش در ۲۸ms پاسخ می‌دهد). فقط Crawl Stats در Search Console عدد واقعی را نشان می‌دهد.
