## ⚠️ پیش از هر چیز: این سایت ایرانی است

چارچوب استاندارد سئوی محلی حول **Google Business Profile** می‌چرخد (۲۵٪ وزن) و ارجاعاتش به Yelp، BBB، Apple Maps و Chamber of Commerce است. **هیچ‌کدام برای کسب‌وکار ایرانی کاربرد عملی ندارند** — یا در ایران در دسترس نیستند، یا اکوسیستم محلی از آن‌ها استفاده نمی‌کند.

معادل‌های واقعی بازار ایران: **نشان**، **بلد**، و تا حدی Google Maps که هنوز توسط بخشی از کاربران استفاده می‌شود.

به همین دلیل دو امتیاز گزارش شده: خام (طبق چارچوب استاندارد) و تعدیل‌شده (با کنار گذاشتن بُعد GBP و توزیع مجدد وزن). توصیه‌های مربوط به BBB و Chamber of Commerce عمداً حذف شده‌اند چون در این بازار بی‌اثرند.

## نوع کسب‌وکار و صنعت

**نوع:** دایرکتوری چندمکانی (نه یک کسب‌وکار محلی منفرد).

این تمایز مهم است: `istgahedandan.ir` خودش یک مطب نیست، بلکه **۲۶۹ کسب‌وکار محلی** (مطب و کلینیک) را روی **۴۹ صفحهٔ منطقه** فهرست می‌کند. یعنی دو سطح سئوی محلی هم‌زمان وجود دارد:

1. هر صفحهٔ دندانپزشک باید مثل یک صفحهٔ کسب‌وکار محلی بهینه باشد (brick-and-mortar)
2. صفحات منطقه باید مثل صفحات فرود جستجوی محلی عمل کنند («دندانپزشکی در شمال تهران»)

**صنعت:** بهداشت و درمان — دندانپزشکی. تشخیص قطعی از `MedicalProcedure`، `Dentist` در schema، و محتوای صفحات.

## یافته‌های بحرانی

### ۱. 🔴 عنوان برند روی ۳۱۶ صفحه دوبار تکرار می‌شود

```
دندانپزشکی دکتر حمیدرضا پاپلی | ایستگاه دندان | ایستگاه دندان
دندانپزشکی در شمال تهران (100% تضمینی) | ایستگاه دندان | ایستگاه دندان
```

علت: `metaTitle` در دیتابیس از قبل شامل «| ایستگاه دندان» است، و `template: "%s | ایستگاه دندان"` در [src/app/layout.tsx:15](src/app/layout.tsx#L15) دوباره اضافه می‌کند.

**دامنهٔ تأثیر:** ۲۶۷ از ۲۶۹ دندانپزشک + ۴۹ از ۴۹ منطقه = **۳۱۶ صفحه**. صفحات خدمات سالم‌اند (`metaTitle` آن‌ها برند ندارد).

پیامد: هدر رفتن فضای محدود عنوان در SERP و رقیق شدن کلمات کلیدی محلی. تکرار برند هیچ ارزشی اضافه نمی‌کند.

**رفع:** در `generateMetadata` صفحهٔ `[slug]`، اگر `metaTitle` از قبل شامل نام سایت است، از `title.absolute` استفاده کنید تا قالب اعمال نشود:

```ts
// src/app/[slug]/page.tsx — داخل generateMetadata
const rawTitle = d.metaTitle || d.title || SITE_NAME;
const title = rawTitle.includes(SITE_NAME)
  ? { absolute: rawTitle }   // قالب اعمال نمی‌شود
  : rawTitle;
```

### ۲. 🔴 صفحات منطقه هیچ structured data ندارند

صفحهٔ `/دندانپزشکی-در-شمال-تهران` — که دقیقاً صفحهٔ فرود جستجوی محلی است — **صفر بلوک JSON-LD** دارد. صفحات دندانپزشک و خدمات schema دارند، صفحات منطقه نه.

این بزرگ‌ترین فرصت از دست رفتهٔ ساختاری است: این صفحات هدف عبارت‌هایی مثل «دندانپزشکی در شمال تهران» هستند و بدون schema، موتورها و سیستم‌های AI رابطهٔ فهرست↔منطقه را نمی‌فهمند.

**رفع پیشنهادی** — افزودن `ItemList` از دندانپزشکان + `BreadcrumbList` + `FAQPage` به `src/lib/seo.ts` و استفاده در `LocationPage`:

```ts
export function locationSchema(loc: {
  slug: string; title: string; shortDesc?: string | null;
  dentists: { slug: string; title: string; address?: string | null }[];
}) {
  return {
    "@context": "https://schema.org",
    "@type": "CollectionPage",
    "@id": `${SITE_URL}/${loc.slug}`,
    name: loc.title,
    description: loc.shortDesc ?? undefined,
    inLanguage: "fa-IR",
    about: { "@type": "Place", name: loc.title },
    mainEntity: {
      "@type": "ItemList",
      numberOfItems: loc.dentists.length,
      itemListElement: loc.dentists.map((d, i) => ({
        "@type": "ListItem",
        position: i + 1,
        item: {
          "@type": ["LocalBusiness", "Dentist"],
          "@id": `${SITE_URL}/${d.slug}`,
          name: d.title,
          url: `${SITE_URL}/${d.slug}`,
          ...(d.address ? { address: { "@type": "PostalAddress", streetAddress: d.address, addressCountry: "IR" } } : {}),
        },
      })),
    },
  };
}
```

### ۳. 🔴 NAP خودِ سایت خالی است

کلیدهای `contact_phone`، `contact_address` و `contact_email` در جدول `Setting` **رشتهٔ خالی** هستند. فوتر آن‌ها را شرطی رندر می‌کند، پس هیچ اطلاعات تماسی روی هیچ صفحه‌ای نمایش داده نمی‌شود.

برای یک دایرکتوری، نبود NAP خودِ برند یعنی هیچ سیگنال موجودیت (entity) برای خود کسب‌وکار وجود ندارد.

**رفع:** پر کردن این سه کلید از پنل ادمین (`/admin/settings`). بدون تغییر کد.

### ۴. 🔴 ۳۱۴ نظر وجود دارد ولی فقط یکی امتیاز دارد

| سنجه | مقدار |
|---|---|
| کل نظرات | ۳۱۴ (همه تأییدشده) |
| **دارای امتیاز عددی** | **۱** |
| دندانپزشکان دارای نظر | ۶۰ از ۲۶۹ (۲۲٪) |
| دندانپزشکان با ۱۰+ نظر | ۶ |
| تازه‌ترین نظر | ۱۴۰۵/۰۴/۰۸ (~۶ هفته پیش) |

پیامدها:
- `aggregateRating` در هیچ صفحه‌ای تولید نمی‌شود (تأیید شد: صفر مورد در HTML) — یعنی **ستاره‌های rich result در SERP نمایش داده نمی‌شوند**
- نظرات ۲۰٪ وزن سئوی محلی دارند؛ عملاً این وزن تلف می‌شود
- فاصلهٔ ۶ هفته‌ای از آخرین نظر، بسیار فراتر از آستانهٔ توصیه‌شدهٔ ۱۸ روز است

**رفع:** فرم نظر ([DentistReviewForm.tsx](src/components/DentistReviewForm.tsx)) امتیاز را می‌فرستد و API هم می‌پذیرد، ولی داده‌های تاریخی (که از وردپرس ایمپورت شده‌اند) امتیاز ندارند. دو کار:
1. امتیاز را در فرم **اجباری** کنید
2. برای ۳۱۳ نظر بدون امتیاز، یا کمپین بازخورد مجدد اجرا شود یا پذیرفته شود که تا انباشت نظرات جدید، `aggregateRating` نداریم

### ۵. 🟠 ساعت کاری برای هیچ دندانپزشکی ثبت نشده

`workingHours` برای هر ۲۶۹ رکورد خالی است. «باز بودن در زمان جستجو» از عوامل شناخته‌شدهٔ رتبه‌بندی محلی است و `openingHoursSpecification` در schema هم تولید نمی‌شود (تأیید شد: صفر مورد).

فیلد در schema دیتابیس وجود دارد و پنل دندانپزشک هم آن را دارد — فقط داده‌اش وارد نشده.

## یافته‌های Schema

آنچه **درست** است در صفحات دندانپزشک:

- نوع صحیح `["LocalBusiness","Dentist"]` — نه `MedicalBusiness` عمومی ✅
- `geo` با دقت ۷ رقم اعشار (بیش از حداقل ۵ رقم) ✅
- `PostalAddress` با `addressCountry: "IR"` و `addressLocality` ✅
- `hasOfferCatalog` با `MedicalProcedure` برای هر خدمت ✅
- `@id` یکتا و برابر با URL صفحه ✅
- `telephone` هماهنگ با NAP قابل مشاهده ✅

اشکالات قابل رفع:

| اشکال | فعلی | باید باشد |
|---|---|---|
| **URL نسبی در `image`** | `/uploads/2023/02/1-5.jpg` | `https://istgahedandan.ir/uploads/…` — schema آدرس مطلق می‌خواهد، الان عملاً نامعتبر است |
| **`@language` نامعتبر** | `"@language": "fa"` | `"inLanguage": "fa-IR"` — `@language` جزو واژگان Schema.org نیست |
| **`areaServed` بیش از حد کلی** | `Country: Iran` | شهر/منطقهٔ واقعی مطب — «کل ایران» برای یک مطب سیگنال محلی را رقیق می‌کند |
| `openingHoursSpecification` | ندارد | بعد از پر شدن `workingHours` اضافه شود |
| `aggregateRating` | ندارد | بعد از جمع شدن امتیازها |

رفع دو مورد اول در [src/lib/seo.ts](src/lib/seo.ts):

```ts
// URL مطلق
const abs = (u?: string | null) =>
  !u ? undefined : u.startsWith("http") ? u : `${SITE_URL}${u.startsWith("/") ? "" : "/"}${u}`;
image: abs(d.featuredImage) ?? SITE_LOGO,

// خاصیت زبان صحیح
inLanguage: "fa-IR",   // به جای "@language": "fa"

// منطقهٔ خدمات واقعی
areaServed: d.locationTitle
  ? { "@type": "City", name: d.locationTitle }
  : { "@type": "Country", name: "Iran" },
```

## سئوی محلی درون‌صفحه — قوی‌ترین بُعد

آنچه خوب کار می‌کند:

- **عنوان و H1 با نیت محلی**: «دندانپزشکی در شمال تهران» — الگوی خدمت + شهر ✅
- **NAP قابل مشاهده** در صفحات دندانپزشک، هماهنگ با schema ✅
- **`tel:` برای کلیک-تماس** در صفحات دندانپزشک ✅
- **صفحات خدمات اختصاصی** — ۷ خدمت، هر کدام صفحهٔ مستقل ✅ (طبق Whitespark عامل #۱ ارگانیک محلی)
- **نقشهٔ تعبیه‌شده** با Leaflet + markercluster ✅
- **sitemap با ۳۸۰ آدرس** و robots.txt صحیح ✅
- **ساختار سلسله‌مراتبی مناطق** (۱ ریشه + ۴۸ زیرمجموعه) ✅

**تست جابه‌جایی (doorway) — قبول:** هر ۴۹ صفحهٔ منطقه `longDesc` بیش از ۲۰۰ کاراکتر و `shortDesc` **یکتا** دارند (۴۹ از ۴۹ متمایز). این سایت الگوی صفحات دروازه‌ای ندارد — نکتهٔ مثبت مهمی است، چون همین الگو بود که در به‌روزرسانی مارس ۲۰۲۴ گوگل سایت‌های مشابه را ۸۰٪ سقوط داد.

کمبودها:

- `tel:` فقط در صفحات دندانپزشک است؛ صفحهٔ اصلی، مناطق و خدمات لینک تماس ندارند
- هیچ FAQ در کل سایت نیست (صفر رکورد) — با اینکه schema و مدل داده پشتیبانی می‌کنند
- نقشه از کاشی‌های **OpenStreetMap** استفاده می‌کند. برای کاربر ایرانی، نشان یا بلد آشناتر و دقیق‌ترند

## ارجاعات و پلتفرم‌های محلی

هیچ ارجاعی به پلتفرم‌های محلی روی سایت قابل تشخیص نیست — نه نشان، نه بلد، نه Google Maps.

برای این بازار، اولویت‌ها:

| پلتفرم | چرا |
|---|---|
| **نشان** (neshan.org) | پرکاربردترین نقشهٔ ایرانی؛ ثبت هر مطب و لینک متقابل |
| **بلد** (balad.ir) | دومین نقشهٔ پرکاربرد |
| **Google Maps / GBP** | هنوز بخشی از کاربران و — مهم‌تر — منبع سیستم‌های AI است |
| دایرکتوری‌های پزشکی ایرانی | مثل پذیرش۲۴، دکترتو — معادل عملی «دایرکتوری صنعتی» |

نکتهٔ مهم دربارهٔ AI: ChatGPT به GBP دسترسی مستقیم ندارد و از ایندکس Bing و منابع ثالث تغذیه می‌شود. برای دیده شدن در پاسخ‌های AI، **Bing Webmaster Tools** و حضور در دایرکتوری‌های قابل‌خزش اهمیت دارد.

## آنچه این تحلیل نتوانست بسنجد

این ارزیابی بر پایهٔ HTML سایت زنده، کد و دیتابیس است. موارد زیر بیرون از دسترس بودند:

- **رتبهٔ واقعی در نتایج محلی** و تحلیل geo-grid — نیاز به ابزار رصد رتبه با موقعیت جغرافیایی
- **پروفایل بک‌لینک و Domain Authority** — نیاز به Ahrefs/Moz/DataForSEO
- **وضعیت ثبت در نشان، بلد و Google Business Profile** — از سمت سایت قابل تشخیص نیست؛ باید مستقیم بررسی شود
- **داده‌های Search Console و GA4** — نرخ کلیک، عبارت‌های واقعی جستجو، و ایندکس شدن ۳۸۰ آدرس sitemap
- **Core Web Vitals میدانی** — به‌ویژه با توجه به اینکه بهینه‌سازی تصویر خاموش است (`images.unoptimized: true`) و ۱۸۶ مگابایت تصویر آپلودی بدون resize سرو می‌شود؛ این موضوع در [`03-issues.md`](./03-issues.md) به‌عنوان مسئلهٔ ۱۲ ثبت شده
- **یکپارچگی NAP بیرون از سایت** — مقایسهٔ آدرس و تلفن هر مطب با آنچه در پلتفرم‌های دیگر ثبت شده

برای تحلیل دیده‌شدن در موتورهای AI (که برای این صنعت رو به رشد است) `/seo geo https://istgahedandan.ir` را جداگانه اجرا کنید.
