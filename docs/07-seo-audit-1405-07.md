**آنچه علت نبود** (هر کدام بررسی و رد شد):

- **تغییر URL:** از ۴۶۴ آدرسی که پیش از افت نمایش داشتند، ۴۰۰ تا الان `200` می‌دهند. ۵۹ آدرس ۴۰۴ مجموعاً **۲ کلیک** در ۸ ماه داشتند.
- **تغییر محتوا:** عنوان و توضیحات صفحات وردپرس (Wayback، آذر ۱۴۰۴) دقیقاً همان‌هایی است که Next.js سرو می‌کند.
- **noindex / robots / canonical:** همه درست. canonical گوگل و کاربر در همهٔ ۶۰ نمونه یکی است.
- **سرعت سرور:** روی خود سرور ۳۰–۱۳۰ms؛ از خارج ایران (ترکیه) TTFB حدود ۱ ثانیه. کند نیست که خزش را متوقف کند.
- **خطای سرور:** در لاگ pm2 هیچ خطای واقعی صفحه نیست؛ همهٔ خطاها `Failed to find Server Action` از اسکنرهای بات‌اند.

### چرا بازیابی کند است

صفحه‌ای که گوگل حذف کرده باید **دوباره کشف و دوباره ارزیابی** شود. دو چیز در کنترل ما این را کند می‌کرد:

1. **کشف:** صفحات منطقه (مثلاً «شمال تهران» با ۸۶ مطب) فقط ۱۲ کارت اول را در HTML داشتند و بقیه با اسکرول بی‌نهایت از `/api/dentists` لود می‌شد — که خزنده‌ها اجرا نمی‌کنند. نتیجه: ۵۶ آدرس بدون هیچ لینک داخلی، فقط از طریق sitemap قابل کشف. وضعیت «URL is unknown to Google» دقیقاً همین را نشان می‌دهد.
2. **ارزیابی کیفی:** ۲۶۴ صفحهٔ دندانپزشک یک متن قالبی مشترک به‌عنوان توضیحات متا **و** پاراگراف «درباره» داشتند — فقط نام عوض می‌شد. این امضای کلاسیک «صفحات تقریباً تکراری» است و با وضعیت «Crawled – currently not indexed» سازگار است.

## ۶. چطور دوباره اندازه بگیریم

همهٔ دستورها از لپ‌تاپ. **تونل sing-box روشن است:** برای سرور با `--interface wlo1` یا `-o BindInterface=wlo1` آن را دور بزنید؛ برای APIهای گوگل از تونل استفاده کنید (بدون آن در دسترس نیستند).

```bash
S="$HOME/.claude/skills/seo/bin/claude-seo"
P=https://istgahedandan.ir/

# روند روزانه / صفحات / کوئری‌ها
$S run gsc_query.py query -p $P --dimensions date --days 120 --json
$S run gsc_query.py query -p $P --dimensions page --days 90 --json --limit 5000

# وضعیت ایندکس گروهی (کند است: ~۱۰ ثانیه برای هر آدرس)
$S run gsc_inspect.py -s $P --batch urls.txt --json

# وضعیت نقشهٔ سایت
$S run gsc_query.py sitemaps -p $P --json

# گوگل‌بات واقعاً چه می‌خزد (فقط از ۱۴۰۵/۰۷/۲۸ به بعد)
ssh -o BindInterface=wlo1 srv "grep -i googlebot /var/log/nginx/istgahedandan.access.log | awk '{print \$9}' | sort | uniq -c"

# IndexNow بعد از تغییرات گسترده
K=$(curl --interface wlo1 -s https://istgahedandan.ir/indexnow-key.txt)
$S run indexnow_submit.py --host istgahedandan.ir --key "$K" \
  --key-location https://istgahedandan.ir/indexnow-key.txt --urls-file urls.txt
```

**شمارش صفحات یتیم:** [`scripts/seo-orphans.py`](../scripts/seo-orphans.py) — خزش BFS از `/` و مقایسه با `sitemap.xml`، فقط با کتابخانهٔ استاندارد پایتون:

```bash
ssh -o BindInterface=wlo1 srv 'python3 - http://127.0.0.1:3004' < scripts/seo-orphans.py
# نتیجهٔ ۱۴۰۵/۰۷/۲۸: sitemap URLs: 379  orphans: 1  — median inlinks 11
```

صفحه‌بندی `/mag/?page=N` را دنبال می‌کند؛ بدون آن مقالات اشتباهاً یتیم شمرده می‌شوند.

**تله‌ها:**
- `parse_html.py` متن را بدون فاصله بین گره‌ها می‌چسباند («دربارهکلینیک») — HTML واقعی درست است؛ قبل از «رفع» آن، خام HTML را ببینید.
- ابزار اسکرین‌شات اسکیل `localhost` را مسدود می‌کند؛ ظاهر را روی سایت زنده چک کنید.
- `sort` روی سرور و لپ‌تاپ ترتیب متفاوتی برای نام‌های فارسی دارد؛ برای مقایسهٔ نسخه‌ها `diff -rq` بزنید نه diff روی خروجی مرتب‌شدهٔ `md5sum`.
